# Level 1 - Product Documentation (WHAT & WHY)

Documentation intended for humans and AI to understand the **product itself** - what we are building
and why. It should be readable by a non-engineer stakeholder.

| File | Answers |
| ---- | ------- |
| `vision.md` | Where is this product going and what does success look like? |
| `problem-statement.md` | What problem are we solving, for whom, and why now? |
| `goals-and-metrics.md` | Business goals + measurable success metrics (KPIs). |
| `users-and-journeys.md` | Target users, personas, and their end-to-end journeys. |
| `requirements.md` | Functional and non-functional requirements. |
| `features.md` | The feature catalogue (with status). |
| `roadmap.md` | Sequenced milestones and their target outcomes. |

**Glossary lives elsewhere:** domain terminology is in the root `CONTEXT.md` (single source of
truth). Link to it; do not duplicate definitions here.

These files start as skeletons. Fill them at kickoff (vision, problem, goals) and grow the rest as
features are conceived - product docs precede architecture, which precedes feature specs.
